# 분류 체계 — 분류가(3)가 쓰는 닫힌 목록

> **갈아끼울 자리 1/3.** 아래를 통째로 지우고 조직의 분류로 바꾸세요.
> 기본값은 오렌지레터(소셜섹터 뉴스레터)의 것입니다.

## 규칙

- **목록은 닫혀 있어야 합니다.** "적절한 분류를 정해줘"라고 열어두면 매번 다른 이름이 나오고 뒤에서 묶을 수 없습니다.
- **칸마다 예시를 두세 개씩** 붙이세요. 예시 없는 분류 목록은 잘 작동하지 않습니다.
- 분류를 바꾸면 `config/format.json`의 `마감_붙일_분류`도 같이 고쳐야 합니다.

## 함께 뽑을 것

분류와 같은 호출에서 아래를 함께 뽑습니다.

| 항목 | 형식 | 비고 |
|---|---|---|
| `분류` | 위 목록 중 정확히 하나 | 없는 이름을 만들지 말 것 |
| `확신도` | `높음` / `보통` / `낮음` | 애매하면 낮게 |
| `조직명` | 문자열 | 원문에 없으면 `[조직명]`으로 비워둘 것. 지어내지 말 것 |
| `행사일` | `YYYY-MM-DD` 또는 `null` | 행사가 열리는 날 |
| `마감일` | `YYYY-MM-DD` 또는 `null` | 신청이 끝나는 날. 행사일과 다름 |
| `마감표현` | 문자열 또는 `null` | "상시 모집"처럼 날짜로 못 적는 경우 원문 그대로 |

### 연도 보정 (중요)

원문에 "3월 5일"만 있고 연도가 없는 경우가 아주 흔합니다. **LLM에게 연도를 맡기지 마세요 — 그냥 채웁니다.**

뽑아낸 날짜에 연도가 없으면 이렇게 처리합니다: **오늘보다 과거면 내년으로 옮깁니다.**
지난 3월에 마감된 공고를 지금 새로 올릴 리는 없기 때문입니다.

## 확신도를 쓸 때 — 우리가 겪은 일

확신도는 "검토 대상을 좁히는" 용도지만, **얼마나 좁혀지는지는 재봐야 압니다.**

오렌지레터는 처음에 높음/낮음 정확도 격차가 20%p였습니다. 그런데 전체 정확도가 88.6% → 92.6%로
올라가는 동안 격차가 8%p로 줄었고, 지금은 **낮음만 봐서는 오류의 39%밖에 못 잡습니다.**
나머지 61%는 높음 구간에 숨어 있습니다.

품질이 나빠져서가 아니라 **좋아지면서 생긴 일**입니다. 그리고 재보기 전까지 아무도 몰랐습니다.
필터를 쓸 거면 필터의 성능을 정기적으로 재세요.

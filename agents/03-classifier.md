# 3. 분류가

내용을 **정해진 칸 중 하나**에 넣고, 날짜를 뽑습니다.

## 판단 기준

**분류 목록은 닫혀 있어야 한다.** "적절한 카테고리를 정해줘"라고 열어두면 매번 다른 이름이 나오고, 뒤에서 묶을 수 없게 됩니다.
오렌지레터는 8개 고정 목록을 쓰고, 각 칸마다 **어떤 게 여기 들어오는지 예시**를 함께 줍니다.

**애매하면 확신도를 낮게 매긴다.** 억지로 하나를 고르게 하지 말고, `높음/보통/낮음`을 함께 내게 합니다.

### 다만 — 확신도를 검토 필터로 쓸 거면 그 필터의 성능을 재세요

여기서 우리가 실제로 틀렸습니다. 원래 이 문서에는 *"낮음으로 온 건만 사람이 보면 되므로 검토량이 크게 줄어든다"*고
적혀 있었습니다. 재보니 아니었습니다.

| | 처음(2026-04) | 지금(2026-08) |
|---|---|---|
| 전체 정확도 | 88.6% | **92.6%** |
| 높음/낮음 정확도 격차 | 20.3%p | **8.0%p** |

**낮음만 검토하면 오류 38건 중 15건(39%)밖에 못 잡습니다. 나머지 61%는 높음 구간에 숨어 있습니다.**
109건을 읽어서 15건을 잡는 필터입니다.

품질이 나빠져서 생긴 일이 아닙니다. **전체 정확도가 올라가는 동안 낮음 구간이 같이 좋아지면서** 변별력이 사라졌습니다.
개선이 설계 전제를 깨뜨린 것이고, **재보기 전까지 넉 달 동안 아무도 몰랐습니다.**

확신도는 여전히 쓸모가 있습니다. 다만 "얼마나 좁혀지는지"는 정기적으로 재야 알 수 있고,
안 재면 문서에 적힌 약속이 조용히 거짓이 됩니다.

**날짜는 두 종류다.** 행사가 열리는 날과 신청이 끝나는 날은 다릅니다. 섞이면 "이미 끝난 행사"를 안내하게 됩니다.

### 연도를 지어내는 문제

원문에 "3월 5일"만 있고 연도가 없는 경우가 아주 흔합니다. LLM은 빈칸을 그냥 채웁니다.

→ **연도 없는 날짜는 규칙으로 보정합니다.** 뽑아낸 날짜가 오늘보다 과거면 내년으로 옮깁니다.
지난 3월 5일에 신청이 끝나는 공고를 새로 올릴 리는 없기 때문입니다. 이건 LLM에 맡기지 말고 코드로 처리하는 편이 안정적입니다.

## 입력 / 출력

**입력**: 문지기를 통과한 본문

**출력**
```
분류: <닫힌 목록 중 하나>
확신도: 높음 | 보통 | 낮음
행사일: <YYYY-MM-DD 또는 없음>
마감일: <YYYY-MM-DD 또는 없음>
마감 표현: <"상시 모집" 같이 날짜로 못 적는 경우 원문 그대로>
판단 근거: <한 줄>
```

## 갈아끼울 자리

분류 목록입니다. 조직의 업무 분류로 바꾸고, **칸마다 예시를 두세 개씩** 붙이세요. 예시 없는 분류 목록은 잘 작동하지 않습니다.

날짜 항목은 조직에 따라 통째로 필요 없을 수도 있습니다.

## 실측

최근 한 달 512건 분류.

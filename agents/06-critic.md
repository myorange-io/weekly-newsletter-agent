# 6. 비평가

초안의 **문제를 지적하고 대안을 냅니다.** 반영은 사람이 결정합니다.

## 판단 기준

**초안가와 반드시 다른 호출이다.** 같은 대화에 이어 붙이면 자기가 쓴 문장을 방어합니다.
통과율이 비정상적으로 높아지고 검수가 장식이 됩니다. 이건 프롬프트로 못 고칩니다. 호출을 나눠야 고쳐집니다.

**고치지 않고 지적한다.** 비평가가 바로 고쳐서 내놓으면 사람이 비교할 대상이 없어집니다.
→ **A안(원래 초안)과 B안(대안)을 나란히** 내고, 무엇을 왜 바꿨는지 적습니다.

**바꿀 게 없으면 바꾸지 않는다.** 뭐라도 고치라고 시키면 멀쩡한 문장을 망칩니다.
"바꿀 필요 없음"도 정상 출력이라고 명시해야 합니다.

**보는 것은 사실이 아니라 품질이다.** 고유명사·숫자 대조는 [사실 검증관](05-fact-checker.md)이 이미 했습니다. 비평가는 규칙 준수·자연스러움·읽는 사람 입장을 봅니다.

### 관점을 여러 개 두려면 비평가도 여러 명

한 명에게 "문체·정확성·읽기 쉬움을 모두 보라"고 하면 어느 것도 제대로 안 봅니다.
관점이 정말 여러 개 필요하면 관점마다 따로 부르고 결과를 모으세요. 다만 **최소 구성에서는 한 명으로 시작**하는 게 낫습니다.

## 입력 / 출력

**입력**: 원문 + 초안 + 문체 규칙 (초안 생성 과정은 제외)

**출력**
```
A안: <원래 초안 그대로>
B안: <대안. 바꿀 필요 없으면 "A안 유지">
바꾼 이유: <B안을 낸 경우>
이슈 목록:
  - <규칙 위반이나 어색한 지점>
```

## 사람에게 넘길 때

A안과 B안을 **나란히 보여주고 고르게 합니다.** B안을 자동 반영하지 않습니다.
자동 반영하면 어느 순간부터 아무도 안 보게 되고, 그때부터 품질이 조용히 떨어집니다.

## 갈아끼울 자리

비평 관점입니다. 조직의 산출물에서 자주 나는 실수를 관점으로 만드세요.
"매번 손으로 고치고 있는 것"이 곧 비평 관점입니다.

## 실측

편집 화면에서 A안·B안을 나란히 띄우고 사람이 고르는 방식으로 운영 중입니다.

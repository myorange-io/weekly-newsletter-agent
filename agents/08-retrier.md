# 8. 재시도 담당

**"기다리면 되는가"**만 판단합니다. 코드는 건드리지 않습니다.

## 판단 기준

### 재시도할 것과 안 할 것을 구분한다

| | 예 | 처리 |
|---|---|---|
| **일시적 실패** | 응답 없음 · 일시 차단 · 서버 오류 | 재시도 대상 |
| **구조적 실패** | 로그인 필요 · 순수 자바스크립트 앱 | **재시도 안 함** |

구조적 실패는 백 번 시도해도 같은 결과입니다. 재시도 목록에 넣으면 상한을 다 쓰고 자원만 태웁니다.
[문지기](02-gatekeeper.md)가 붙인 사유를 그대로 신뢰하면 됩니다.

### "기록 없음"은 실패가 아니라 미실행이다

가장 놓치기 쉬운 부분입니다.

실패 기록이 남은 건은 눈에 띕니다. 그런데 **아예 실행이 안 돼서 아무 기록도 안 남은 건**은 재시도 목록에서 조용히 빠집니다.
배포 교체·함수 조기 종료 같은 이유로 첫 시도가 통째로 날아가면 이렇게 됩니다.

> 실제로 한 건이 **3주 연속** 아무 기록 없이 방치된 적이 있습니다. 나중에 손으로 돌려보니 5초 만에 성공했습니다.

→ **재시도 대상은 "실패한 것"이 아니라 "성공하지 않은 것"**입니다. 기록 없음도 주워야 합니다.
단, 방금 들어온 건은 첫 시도가 아직 진행 중일 수 있으니 유예 시간을 둡니다. 안 그러면 같은 건을 두 경로가 동시에 처리합니다.

### 간격과 상한을 실측으로 정한다

즉시 재시도 몇 번으로는 수 시간 지속되는 차단을 못 넘깁니다. 오렌지레터는 **1시간 간격 · 최대 24회**로 하루를 덮습니다.
그리고 **오래된 회차는 대상에서 뺍니다.** 안 그러면 영영 회복 안 될 건이 무한히 재시도됩니다.

### 실행 위치를 확인한다

지역 차단이 원인이라면 재시도 위치가 결과를 바꿉니다. 차단하는 지역에서 계속 재시도하면 상한만 소진합니다. → [수집가](01-collector.md)

## 입력 / 출력

**입력**: 성공하지 않은 건 목록 (실패 기록 + 기록 없음)

**출력**
```
대상: <n건>
제외: <구조적 실패 n건 — 사유별>
결과: 성공 n건 / 재시도 예정 n건 / 상한 소진 n건
```

## 갈아끼울 자리

간격·상한·유예 시간. 전부 조직의 실패 양상에 맞춰 실측으로 정합니다. 처음에는 넉넉히 잡고 로그를 보면서 조입니다.

## 실측

최근 한 달 8건 재시도 발생.

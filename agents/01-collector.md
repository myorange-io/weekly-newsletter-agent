# 1. 수집가

원자료에서 **본문 텍스트를 뽑아내는 것**만 합니다. 잘 뽑혔는지 판정하는 일은 [문지기](02-gatekeeper.md)가 합니다.

## 판단 기준

**한 가지 방법에 의존하지 않는다.** 오렌지레터는 2단계로 시도합니다.

1. **정적 추출** — HTML을 직접 파싱합니다. 국내 게시판·CMS 종류마다 본문이 담기는 위치가 달라서, 사이트별 추출 위치 목록을 두고 순서대로 맞춰봅니다. 빠르고 비용이 없습니다.
2. **리더 API 폴백** — 1단계 결과가 부족하면 외부 리더 서비스로 넘깁니다. 자바스크립트로 그려지는 페이지가 여기서 살아납니다. 느리고 비용이 있으므로 **1단계로 되면 부르지 않습니다.**

**원문을 건드리지 않는다.** 요약·정리·번역은 뒷단의 일입니다. 수집가가 손대면 뒤에서 사실 검증을 할 원본이 사라집니다.

**주소를 먼저 정리한다.**
- 단축 URL은 실제 주소로 펼칩니다. 펼치지 않으면 어떤 사이트인지 알 수 없어 이후 판단이 전부 어긋납니다.
- 추적 파라미터(`utm_*` 등)는 제거합니다. 같은 글이 다른 글로 취급되는 걸 막습니다.
- 문자 인코딩을 확인합니다. 오래된 국내 사이트는 UTF-8이 아닌 경우가 많고, 그대로 읽으면 본문이 깨진 채로 통과합니다.

**느린 곳은 느리다고 알고 기다린다.** 응답이 오래 걸리는 도메인 목록을 따로 두고 대기 시간을 늘립니다. 일괄 타임아웃을 짧게 잡으면 멀쩡한 사이트가 매번 실패합니다.

**실행 위치가 결과를 바꾼다.** 국내 일부 사이트는 해외 IP를 차단합니다. 클라우드에서 돌리면 국내에서 잘 되던 수집이 실패합니다. 수집만 국내 리전에서 돌리는 식의 배치가 필요할 수 있습니다.

## 입력 / 출력

**입력**: 원자료 위치 (URL·파일 경로 등)

**출력**
```
본문 텍스트: <추출한 원문>
제목: <있으면>
요약 메타데이터: <페이지가 스스로 제공하는 설명. 본문과 구분해서 보관>
수집 경로: 정적 추출 | 리더 폴백
실패 사유: <실패했으면 무엇이 막았는지>
```

메타데이터를 **본문과 합쳐서 넘기지 않는 게 중요합니다.** 합쳐 놓으면 문지기가 "본문이 있다"고 오판합니다.

## 하지 않는 일

- 내용이 쓸만한지 판정 → 문지기
- 요약·분류 → 분류가
- 실패했을 때 다시 시도 → 재시도 담당

## 갈아끼울 자리

원자료 종류입니다. 웹페이지가 아니라 PDF 보고서라면 1단계는 PDF 텍스트 추출, 2단계는 OCR이 됩니다.
설문 응답이라면 추출 자체가 필요 없고 주소 정리 항목도 통째로 빠집니다. **2단계 구조와 "원문을 건드리지 않는다"만 남기면 됩니다.**

# 5. 사실 검증관

초안에 나온 것이 **원문에 실제로 있는지** 대조합니다. 문장 품질은 보지 않습니다.

## 판단 기준

**초안이 어떻게 나왔는지 모르는 상태로 본다.** 검증관에게는 **원문과 초안만** 줍니다.
"이런 규칙으로 썼어"라고 알려주면 그 규칙을 근거로 통과시킵니다.

**대조 대상은 고유명사와 숫자다.**
- 조직·기관 이름 → 원문에 그 이름이 있는가
- 날짜·금액·인원 → 원문에 그 숫자가 있는가

문장이 자연스러운지, 말투가 맞는지는 [비평가](06-critic.md)의 일입니다.

### 없으면 지우지 말고 빈칸으로 남긴다

원문에서 조직명을 못 찾았을 때 초안에서 그냥 지우면, 읽는 사람은 누가 하는 행사인지 모르게 됩니다.
→ `[조직명]` 같은 **빈칸 표시**로 남기고 사람이 채우게 합니다.

빈칸 표시가 들어온 건은 **검증 실패가 아닙니다.** LLM이 "못 찾았다"고 정직하게 말한 것이므로 통과시키고, 사람에게 넘깁니다.

### 대조가 무의미한 경우는 면제한다

- 전용 API로 가져온 검증된 내용
- 이름을 안정적으로 분리할 수 없는 형식 (인터뷰 인용문 등)

이런 건 통과시킵니다. 무리하게 대조하면 멀쩡한 결과가 대량으로 반려됩니다. **면제 조건을 명시적으로 적어두는 것**이 중요합니다. 안 적으면 나중에 아무도 왜 통과하는지 모릅니다.

### 두 층으로 나눈다

| | 상시 검증 | 요청 시 검증 |
|---|---|---|
| 대상 | 모든 건 | 사람이 지목한 건 |
| 방법 | 문자열 대조 (LLM 호출 없음) | LLM으로 원문 대 초안 정밀 비교 |
| 비용 | 없음 | 있음 |

상시 검증은 비용이 안 드는 방식으로 전수에 겁니다. 정밀 검증은 필요할 때만 부릅니다.

## 입력 / 출력

**입력**: 원문 + 초안 (초안 생성 과정은 제외)

**출력**
```
판정: 통과 | 불일치
불일치 항목: <원문에 없는 고유명사·숫자>
빈칸 표시: <있으면, 사람이 채워야 할 자리>
```

## 갈아끼울 자리

대조할 필드 목록입니다. 조직의 산출물에서 **틀리면 가장 곤란한 항목**부터 넣으세요.
후원자 편지라면 금액과 이름, 사업보고서라면 수치와 기간입니다.

## 실측

최근 한 달 512건 전수 상시 검증.

# 9. 정비공

**"코드를 고쳐야 하는가"**를 판단합니다. 주 1회 돕니다.

자동화를 만들어두면 시간이 지나면서 조용히 낡습니다. 사이트 구조가 바뀌고, 새로운 형태의 원자료가 들어옵니다.
정비공이 없으면 **아무도 모르는 사이에 실패율이 올라갑니다.**

## 판단 기준

### 진단 먼저, 처방은 그 다음

그 주에 실패한 건을 모아 하나씩 원인을 규명합니다.

- 주소를 펼쳐야 하는 형태인가
- 응답이 느린 곳인가
- 본문 위치가 기존 목록에 없는가 → **직접 후보를 탐색해봅니다**
- 위 어디에도 안 걸리는가 → `사람 검토 필요`

처방은 원인마다 정해져 있습니다. 오렌지레터는 네 가지입니다.

| 처방 | 무엇을 바꾸나 |
|---|---|
| `단축 주소 호스트 추가` | 펼쳐야 할 도메인 목록에 추가 |
| `느린 도메인 추가` | 대기 시간을 늘릴 도메인 목록에 추가 |
| `본문 위치 추가` | 추출 위치 목록에 추가 |
| `사람 검토 필요` | 자동 처방 없음 |

### 패치는 제안까지만 한다

정비공은 코드를 고칠 수 있습니다. 하지만 **바로 반영하지 않습니다.**
별도 브랜치에 올리고 **PR로 사람에게 승인을 받습니다.** 진단 결과를 PR 본문에 붙여서, 왜 이 패치인지 읽고 판단할 수 있게 합니다.

자동으로 반영하면 두 가지가 무너집니다. 잘못된 처방이 조용히 들어가고, 사람이 실패 양상을 볼 기회를 잃습니다.
**실패 목록을 매주 읽는 것 자체가 운영입니다.**

### 고칠 게 없어도 보고한다

이게 의외로 중요합니다. 정비공은 **"이번 주 수정사항 없음"도 통보**합니다.

아무 소리도 안 나는 자동화는 **잘 돌아가는 것과 죽은 것을 구분할 수 없습니다.**
매주 뭔가 오면 안 온 주에 바로 알아챕니다.

## 입력 / 출력

**입력**: 그 주에 실패한 건 목록

**출력**
```
진단: <건별 원인과 처방>
자동 처방 가능: n건
사람 검토 필요: n건
제안한 패치: <브랜치 · PR 링크. 없으면 "수정사항 없음">
```

이 결과를 **팀 메신저로 통보**합니다. 성공·수정없음·실패 세 가지 상태를 구분해서 보냅니다.

## 갈아끼울 자리

처방 목록입니다. 조직에서 **반복해서 손으로 고치고 있는 것**이 곧 처방 후보입니다.
같은 수정을 세 번 했다면 그건 처방으로 만들 때가 된 것입니다.

자동 패치가 부담스러우면 **진단과 보고만 하고 처방은 사람에게 넘기는 형태**로 시작해도 충분합니다.
실패 목록을 매주 읽게 만드는 것만으로도 대부분의 가치가 나옵니다.

## 실측

매주 1회 자동 실행. 최근 한 달 4회 · 12주 연속 무중단.

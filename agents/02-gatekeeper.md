# 2. 문지기

**AI를 부르기 전에 멈추는 일**만 합니다. 아홉 명 중 가장 중요합니다.

## 왜 필요한가

빈 내용이 LLM에 닿으면 LLM은 "모르겠다"고 하지 않습니다. **주소와 도메인 이름만 보고 그럴듯한 것을 만들어냅니다.**

> 게시글이 없는 빈 게시판에서 메뉴·버튼 같은 UI 문자열만 추출된 적이 있습니다.
> 그게 본문으로 통과했고, LLM은 **존재하지 않는 재단 이름과 사업명, 마감일을 지어냈습니다.**
> 형식이 완벽해서 눈으로는 걸러지지 않았습니다.

프롬프트에 "지어내지 마"를 백 번 써도 이건 막히지 않습니다. **입력을 막아야 막힙니다.**

## 판단 기준

아래 중 하나라도 해당하면 **반려**합니다.

| 사유 | 어떻게 알아보나 |
|---|---|
| `로그인 필요` | 본문에 로그인·회원가입 안내만 있다 |
| `빈 게시판` | 게시판 틀은 있는데 글 내용이 없다 |
| `봇 차단` | 보안 확인·차단 안내 페이지다 |
| `내용 부족` | 본문이 하한선에 못 미친다 |
| `UI만 추출` | 메뉴·버튼 같은 화면 요소 문자열만 있다 |
| `이미지 전용` | 본문은 거의 없고 이미지만 있다 (포스터·전단) |

### 특히 조심할 것

**메타데이터를 본문으로 인정하지 않는다.** 페이지가 스스로 제공하는 설명(OG 태그 등)은 본문이 비었을 때도 남아 있습니다.
이걸 본문에 합산하면 "충분하다"는 오판이 납니다. 실제로 본문 19자짜리 페이지가 메타데이터 덕에 통과해서, 잘린 설명 속 날짜를 마감일로 잘못 읽은 적이 있습니다.
→ **본문 자체에 하한선을 따로 겁니다.**

**차단 페이지도 자기 메타데이터를 내려줍니다.** 보안 확인 페이지가 자기 제목을 OG로 주는 경우가 있어, 그게 통과하면 실제 콘텐츠인 양 분석됩니다.

**검증된 경로는 면제한다.** 전용 API로 가져온 내용(영상 제목·공식 임베드 등)은 짧아도 진짜입니다. 길이만 보고 막으면 정상 건이 걸립니다.

**게이트 하한이 두 개면 안 된다.** 수집을 계속할지 정하는 하한과 AI에 넣을지 정하는 하한이 따로 있으면,
둘이 어긋나는 순간 조용히 무너집니다. 오렌지레터에서 실제로 그랬습니다 — 본문이 사실상 빈 페이지가
메타데이터 덕에 '충분' 판정을 받아 폴백을 건너뛰었고, 잘린 설명 속 날짜가 마감일로 들어갔습니다.
→ 두 하한을 쓸 거면 **어느 쪽이 더 엄격한지 문서에 못 박고**, 한쪽을 고칠 때 반드시 다른 쪽을 같이 보세요.
(이 저장소는 `config/gate.json`에 `본문_하한`과 `수집_계속_하한`으로 나눠 두고 관계를 주석에 적어놨습니다.)

**게이트가 이상하게 굴면 게이트를 의심하기 전에 들어오는 것을 의심하세요.** 화면 요소가 본문에 섞여 들어오면
멀쩡한 페이지가 반려됩니다. 그건 문지기 버그가 아니라 [수집가](01-collector.md) 버그입니다.

## 반려는 실패가 아니다

반려된 건은 **사람에게 직접 입력을 요청하는 정상 경로**로 넘어갑니다.
목표는 통과율을 높이는 게 아니라 **못 읽는 걸 못 읽는다고 정확히 말하는 것**입니다.

성공률을 올리려고 하한선을 낮추면 숫자만 오르고 품질이 무너집니다. 게이트를 낮추기 전에 [수집가](01-collector.md)를 고치세요.

## 입력 / 출력

**입력**: 수집가의 출력 (본문 · 메타데이터 · 수집 경로) — 반드시 분리된 상태로

**출력**
```
판정: 통과 | 반려
사유: <반려일 때 위 표의 사유 중 하나>
사람에게 요청할 것: <반려일 때, 직접 입력받아야 할 항목>
```

## 갈아끼울 자리

- **하한선 수치** — 조직의 원자료 길이에 맞춰 실측으로 정합니다. 처음에는 넉넉히 잡고 반려된 걸 눈으로 확인하면서 조입니다.
- **사유 목록** — 원자료가 웹페이지가 아니면 사유가 통째로 달라집니다. 스캔 문서라면 `OCR 실패`·`손글씨`, 설문이라면 `무응답`·`장난 응답`이 됩니다.

## 실측

최근 한 달 8건 반려.

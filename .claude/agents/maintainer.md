# 9. 정비공 (실행)

판단 기준 전문: [`agents/09-maintainer.md`](../../agents/09-maintainer.md)

## 절차

```bash
node scripts/triage.mjs
```

실패를 사유별로 묶고 사유마다 정해진 처방을 붙여 보고한다.

## 네가 할 일 — 진단을 처방으로 옮기기

스크립트는 사유별 일반 처방까지만 낸다. **구체적으로 무엇을 고칠지는 네가 제안한다.**

1. 실패한 건의 `work/<id>/raw.md`를 실제로 열어본다.
2. `config/gate.json`에서 무엇을 바꾸면 이 건이 살아나는지 찾는다.
   - 화면 문자열이 본문에 섞였다 → `화면요소_표지`에 그 사이트 문구 추가
   - 리더 폴백이 안 돌았다 → `수집_계속_하한` 확인
   - 새로운 차단 문구 → `봇차단_표지`에 추가
3. **바꿀 내용을 제시하되 파일을 직접 고치지 않는다.** 사람이 승인한다.

## 자동으로 반영하지 않는 이유

두 가지가 무너진다. 잘못된 처방이 조용히 들어가고, **사람이 실패 양상을 볼 기회를 잃는다.**
실패 목록을 매주 읽는 것 자체가 운영이다.

## 고칠 게 없어도 보고한다

`✓ 이번 주 수정사항 없음`도 반드시 사람에게 전한다.
아무 소리도 안 나는 자동화는 **잘 돌아가는 것과 죽은 것을 구분할 수 없다.**

## 처방을 늘릴 때

**같은 수정을 세 번 했다면 그건 처방으로 만들 때가 된 것이다.** `scripts/triage.mjs`의 처방 표에 추가하라.
